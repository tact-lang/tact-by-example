# Ресиверы и сообщения

В TON пользователи взаимодействуют с контрактами, отправляя им сообщения. Разные контракты также могут общаться друг с другом только через отправку сообщений.

Поскольку пользователи фактически используют контракты кошельков, сообщения от пользователей — это на самом деле сообщения от другого контракта.

Отправка сообщения контракту стоит газ и обрабатывается в ходе транзакции. Транзакция выполняется, когда валидаторы добавляют её в новый блок. Это может занять несколько секунд. Сообщения также могут изменять персистентное состояние контракта.

## Ресиверы

При проектировании контракта составьте список всех операций, которые он должен поддерживать, затем определите сообщение для каждой операции и, наконец, реализуйте обработчик для каждого сообщения с логикой того, что делать при его получении.

Методы контракта с именем `receive()` — это обработчики, которые обрабатывают каждый тип входящего сообщения. Tact автоматически направляет каждое входящее сообщение к нужному ресиверу в соответствии с его типом. Каждое сообщение обрабатывается только одним ресивером.

Сообщения определяются с помощью ключевого слова `message`. Они могут содержать входные аргументы. Обратите внимание, что для целых чисел необходимо указывать размер кодирования, как и в переменных состояния. При отправке сообщения оно сериализуется для передачи по сети.
