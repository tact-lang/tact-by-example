# Неограниченные массивы — список задач

В целом бесконечные структуры данных, способные вырасти до миллиардов элементов, очень сложно реализовать в блокчейне. По мере роста постоянного состояния контракта операции чтения и записи становятся всё дороже по газу. В крайних случаях они могут стоить больше лимита газа на транзакцию, что сделает контракт непригодным для использования.

Поэтому **важно проектировать контракты с верхней границей размера состояния.** Но как тогда реализовать список задач, способный масштабироваться до миллиардов элементов?

## Бесконечно масштабируемый список задач

Секрет бесконечной масштабируемости в TON — шардирование данных между несколькими контрактами. Для этого мы можем использовать паттерн «родитель — потомок».

В этом примере каждый новый элемент списка задач развёртывается как отдельный дочерний контракт. Пользователи взаимодействуют с дочерними контрактами через контракт `TodoParent`.

Когда пользователь отправляет сообщение `NewTodo` родителю, тот развёртывает нового потомка для хранения нового элемента. Если пользователь хочет узнать детали элемента, он может вызвать геттер `todoAddress()` у родителя, а затем вызвать геттер `details()` у дочернего контракта.
